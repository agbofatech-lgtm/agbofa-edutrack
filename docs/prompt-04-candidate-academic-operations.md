## Authorization, provenance and data boundaries

- Phase 01/02 session authentication, CSRF and existing identity RBAC apply to every academic route. Each action has a distinct `academic.*` permission code in `backend/academic/permissions.py`; scope is derived from the trusted institution URL and object FK, not a caller's role claim. Institution discovery and `context.permissions` only report **effective grants for that institution**. UI visibility is a hint; every read/write rechecks the server authorization and resource. Register/guardian/BA-0/weekly/mock reads are separate. The UI's name selectors require the companion `academic.candidate.read` grant even when a non-read operation has its own separate API authority.
- **No roles, permission assignments, mock level, approval mapping, academic calendars, subjects, class labels or marking scales are seeded.** `ACADEMIC_MOCK_PREPARER_ROLE_CODE`, `ACADEMIC_MOCK_APPROVER_ROLE_CODE` and `ACADEMIC_BECE_LEVEL_CODE` default to empty. Do not use a Local Manager role as a mock approver. The Owner must authorize the JHS Contact Person, Headmaster and Basic 9 mappings and exact per-institution grants before use. Staff affiliation and permission membership are distinct; a code alone never becomes mock approval authority. BA-0/weekly checks also require distinct actors; approval is not a maker's or mark editor's self-approval.
- Academic write services lock the institution and target rows inside transactions, check current versions, validate the approved Phase 03 configuration/date/placement dependencies and either commit all changes plus audit or roll back. Bulk imports and mark/roster writes are bounded; stale writes return 409. Replaying an applied import with the original actor/key/payload returns the original IDs without duplicate creation. A changed key/payload or stale preview is refused.
- Audit events use an allow-list and include institution, record IDs, versions, counts, before/after *digests* and correction IDs, **not** candidate/guardian names, phone numbers, raw mark arrays, CSV payloads or reasons. Authorized before/after private evidence is stored in dedicated scoped domain history tables. Approved source rows and child observations/marks are guarded against ordinary ORM edits/deletes and bulk manager writes; SHA-256 snapshot digests and predecessor/successor links preserve provenance. Database owners/direct SQL, triggers, retention and offsite immutability require further governance.
- Candidate 360° labels restricted or unimplemented sections rather than implying zero results. Available baseline/weekly/mock histories are capped at 50 with count/truncation; candidate-scoped activity records strip **other candidates' participants, marks and quality**. Paginated register/revision views provide older records. A relationship's inactive/unauthorized contact is masked in Candidate 360°/link responses; the separately scoped guardian directory may still show contact to a user granted `academic.guardian.read`. That directory is an administrative view, not guardian access.

## Safe operational sequence (once separately authorized)

1. Approve institution/release/year/class/stream/subject-offering/teacher structure under Phase 03 governance. Configure only Owner-approved role/level mappings and grants, with no assumption of a school record, date policy or score maximum.
2. Register a candidate and placement or preview a ≤100-row CSV. Resolve duplicates/invalid rows; commit the *same* preview key and payload. Use a reason and current version to correct identity/status. Record guardian link authorization separately. Subsequent placements in the same academic year must not overlap.
3. Enter BA-0 source date/label and explicit mark states, submit and approve with an independent checker. Request correction with a reason; another scoped authorizer decides it; edit and reapprove the successor, never the approved predecessor.
4. Schedule weekly assessment with teacher assignment and raw maximum; record expected/attended/absent/not-assessed roster; mark each declared eligible subject, allowing scored zero. A different reviewer moderates, an independent approver freezes, and only a resolved approved blueprint can publish. Correct through a new successor and republish, retaining old evidence.
5. For a *configured Basic 9 level only*, an authorized JHS Contact Person prepares a mock; eligible subject teachers or that preparer enter marks. Independent reviewer moderates; Headmaster-mapped, privileged MFA account approves/publishes. Local Manager is not the approver. No allowance or finance action follows automatically.
